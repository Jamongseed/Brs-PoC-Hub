PoC-H 시나리오 요약

MAIN(메인 페이지)이 THIRDPARTY(서드파티) 위젯을 로드한 상태에서, 사용자가 위젯의 닫기 버튼을 누르는 순간(위젯 DOM 제거)을 MutationObserver가 감지해 추가 스크립트(loader.js)를 동적으로 삽입합니다.

이후 loader.js는 payload.b64를 받아 atob로 디코딩하고, 디코딩된 stage2 스크립트를 페이지에 <script id="pocH_stage2"> 형태로 삽입해 실행합니다. stage2는 화면 배지를 표시하고, XMLHttpRequest 프로토타입을 후킹하여 MAIN에서 발생하는 XHR 요청 메타를 /mirror 엔드포인트로 미러링합니다.
  1. 서드파티 로드: MAIN이 THIRDPARTY sdk.js를 로드
  2. 위젯 삽입: sdk.js가 iframe(widget.html)을 DOM에 삽입
  3. 트리거: 사용자가 위젯 닫기 버튼 클릭 → 위젯 컨테이너 DOM 제거
  4. MO 감지: MAIN의 gate.js가 DOM 제거(removedNodes)를 감지
  5. 1차 로딩: 감지 직후 THIRDPARTY의 loader.js를 동적 삽입
  6. 2차 실행: loader.js가 payload.b64 → atob → stage2 실행
  7. 후킹/미러링: stage2가 XHR 후킹 활성화 + /mirror로 요청 메타 미러링
주의
  • 데모 목적입니다. 실제 계정/민감정보를 입력하지 마세요.
  • stage2는 script#pocH_stage2로 삽입됩니다. 페이지에서 “Injected 제거(방어자)” 버튼으로 제거할 수 있습니다.
  • 제거 후에는 gate.js가 제거 이벤트를 감지해 재주입을 시도할 수 있습니다. (쿨다운이 걸릴 수 있음)
  • stage2의 미러링 요청은 브라우저에서 정상 UI처럼 보이기 쉬워서, THIRDPARTY 서버 로그(또는 Network 탭의 /mirror 요청)로 확인하는 것이 가장 확실합니다.
