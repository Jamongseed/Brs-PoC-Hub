PoC-C 시나리오 요약

정상 사이트(MAIN)가 서드파티 SDK(THIRDPARTY)를 로드하는 상황에서, 위젯(iframe) 상호작용(postMessage)을 트리거로 SDK가 로그인 폼 제출 목적지(form.action)를 서드파티 수집 엔드포인트로 바꿔치기하고, preventDefault() 후 form.submit()로 네이티브 제출을 수행하는 데모입니다.
  1. 서드파티 스크립트 로드: MAIN이 <script src="(thirdparty)/sdk.js">를 로드
  2. 광고 위젯 iframe 삽입: SDK가 <iframe src="(thirdparty)/widget.html">를 페이지에 추가
  3. postMessage로 armed 전환: 위젯에서 parent.postMessage(...) → SDK가 armed=true
  4. 제출 가로채기: 로그인 클릭 시 submit 흐름을 막고(preventDefault), form.action을 (thirdparty)/collect로 변경
  5. 네이티브 submit 수행: form.submit()로 실제 POST를 THIRDPARTY로 전송
이 PoC가 강조하는 포인트
  • 단순 submit 이벤트 감지만으로는 놓치기 쉬운 흐름(preventDefault 후 form.submit())을 재현합니다.
  • 프로젝트의 page_hook 기반 FORM_NATIVE_SUBMIT → FORM_SUBMIT 변환이 PoC-C에 직접 대응되는 구조입니다.
주의
  • 이 PoC는 데모 목적입니다. 입력칸에는 실제 계정/비밀번호를 입력하지 마세요.
  • 일부 구현은 origin(예: 특정 THIRDPARTY 도메인) 조건에 의존할 수 있습니다. Hub에 등록된 MAIN/THIRDPARTY 링크로 테스트하세요.
